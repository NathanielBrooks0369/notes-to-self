# Healthtech Signed URL Downloads: Private Documents, Storage Egress Tradeoffs

Short answer: use a short-lived signed link for a healthtech document only after the application has checked ownership, and choose the storage provider by its failure behavior and egress model rather than by its headline storage price. The application should authorize a stable document ID, resolve the current object key, check that the object exists, and then issue one link for the intended download. The browser gets bytes directly; the application does not proxy the file.

That boundary is the important part. A signed URL is a bearer credential, not a substitute for an authorization service. If a medical intake file is attached to the wrong account in the database, a perfectly valid signature can still deliver the wrong file. Keep the bucket and key private, keep the link lifetime short enough for the client to start and finish a normal transfer, and record the authorization decision separately from the storage request.

## How should private document downloads balance signed URLs, storage, and egress?

Start with the download path, not the provider catalog. The request should enter an authenticated application endpoint, carry a document ID rather than a raw object path, and pass an access check that understands patient, organization, and case boundaries. The service then reads the current key from its database, verifies presence, creates the signed URL, and returns it. A direct client download follows. Each step needs a distinct metric because “link issued” is not the same as “user received the first byte.”

For a healthtech SLO, measure authorized requests that receive a link, downloads that begin before expiry, time to first byte, completed versus abandoned transfers, and missing-object responses. A 403 can mean an expired link or a policy mismatch; a missing object can mean a broken database mapping. Those are different incidents with different rollback actions. Don't collapse them into one generic download error.

The capacity plan needs more than stored gigabytes. Model normal clinician retrieval, a support-driven export burst, concurrent downloads of the largest allowed file, retries after a mobile connection drops, and the egress generated by a failed client that restarts from byte zero. For example, a 2 GB diagnostic video downloaded twice by a client that retries from the beginning is a 4 GB delivery event before the clinician sees a usable file; multiply that pattern across tenants, regions, and a support export, then compare it with the transfer allowance and request pricing in the candidate's current terms. The storage total can remain flat while that read path grows sharply. A provider comparison that only multiplies storage volume by a monthly rate is not a capacity plan.

## The authorization boundary is the product boundary

Use a single application operation for the decision. Every caller should supply a document identifier; no caller should learn how to assemble a bucket name or key. The database owns access policy, current location, replacement history, and lifecycle status. Object storage owns bytes and delivery. This separation makes a permission correction or object relocation possible without changing the public API.

The implementation can stay small while preserving those responsibilities:

```go
package downloads

import (
	"context"
	"errors"
	"time"
)

var ErrDenied = errors.New("document access denied")
var ErrMissing = errors.New("document object missing")

type Document struct {
	Key       string
	OwnerID   string
	ExpiresAt time.Time
}

type Repository interface {
	FindDocument(ctx context.Context, id, subjectID string) (Document, error)
}

type Objects interface {
	Exists(ctx context.Context, key string) (bool, error)
	SignDownload(ctx context.Context, key string, ttl time.Duration) (string, error)
}

func IssueLink(ctx context.Context, repo Repository, objects Objects, id, subjectID string) (string, error) {
	doc, err := repo.FindDocument(ctx, id, subjectID)
	if err != nil {
		return "", ErrDenied
	}
	if doc.Key == "" {
		return "", ErrMissing
	}
	present, err := objects.Exists(ctx, doc.Key)
	if err != nil || !present {
		return "", ErrMissing
	}
	return objects.SignDownload(ctx, doc.Key, 10*time.Minute)
}
```

The ten-minute value is an example policy, not a universal answer. A large diagnostic video on a slow connection may need a different window than a small PDF, while a longer window increases the exposure of a leaked bearer credential. Decide from transfer size, client behavior, and the access-control risk, then test the decision against the SLO.

On writes, use the same discipline. Upload to a non-public key, commit the database reference only after the object is complete, and treat a rename as a copy followed by a reference update. Multipart upload is useful for large objects, but it adds completion and abandoned-part cleanup to the runbook; the storage service's documented lifecycle and cleanup semantics must be verified before production use.

## What should a provider review cover beyond storage cost?

Put every candidate through the same worksheet. Amazon S3 presigned URLs, Cloudflare R2 signed URLs, Supabase Storage, and Firebase Storage may expose different credential, policy, regional, and billing surfaces; the names alone do not establish equivalent behavior. Confirm each item from current primary documentation and a small test account before committing the architecture.

| Review area | Question that must have an observed answer | Failure mode if skipped |
| --- | --- | --- |
| Authorization | Can the application keep ownership checks ahead of signing? | A valid link exposes a document from the wrong tenant |
| Delivery | Does the client receive bytes directly, with the expected expiry behavior? | The app becomes a bandwidth bottleneck or links outlive policy |
| Egress | What is billed for ordinary reads, retries, and cross-region delivery? | A low storage estimate hides the real monthly variable |
| Large objects | What are the multipart completion, abort, and retry rules? | Incomplete uploads consume capacity or remain unaccounted for |
| Recovery | Can an object be restored, copied, or revalidated independently? | A database fix cannot repair an absent byte stream |
| Observability | Can link issuance and first-byte success be correlated without logging secrets? | An access incident looks like a network incident |

Cost belongs in the worksheet, but it should not be the only column. Compare storage, request charges, data transfer, replication, retrieval, and operational labor over the same traffic scenarios. Backblaze's public pricing page is a useful reminder that transfer terms are provider-specific; AWS's multipart-upload overview shows why large-file behavior needs its own operational review. Pricing changes. Your mileage may vary, and the invoice should be rechecked against the workload before a renewal or migration.

Avoid logging the complete signed URL: query parameters commonly carry the credential. Log a request ID, document ID, tenant ID, expiry bucket, provider operation, and outcome instead. Access logs need retention and redaction rules suitable for health data, and traces should make it possible to follow an authorization decision without copying the document itself into telemetry.

## Verification and rollback before rollout

Build a fixture with one authorized subject, one denied subject, an existing object, and a database row pointing at a missing object. Verify that only the authorized subject gets a link, that the link downloads before expiry, and that an expired link is rejected. Verify that the denied path does not reveal whether another tenant's object exists. A browser test alone is too shallow; run the same checks through the application endpoint and the storage response.

Roll out behind a document-class flag. Compare link issuance, first-byte success, completion rate, latency, and egress against the existing baseline, then increase the cohort only while the download SLO and error budget remain healthy. If the signals move, stop issuing new links for that class, preserve the database mapping for investigation, and validate a repaired flow with the same fixture before restoring issuance. Short expiry limits already-issued links; it does not repair an authorization bug, so revoke or rotate any broader credential involved in the incident.

The test should include a 403, a timeout, a client retry, and a provider-side missing-object result, even when the happy path is stable. These cases define the useful runbook.

## Where this design is not suitable

The catch is that short-lived private delivery is a poor fit for permanent public assets, anonymous downloads, immutable legal retention, or high-contention collaborative editing. Use a public-content delivery design for public assets, and use a storage or records system with the required retention and conditional-write guarantees for regulated immutability. Do not make a signed URL carry a requirement that belongs to another control plane.

It is also a poor fit when the team cannot operate the authorization record, expiry policy, and recovery checks. In that case, choose a managed workflow whose access model matches the product, or postpone direct delivery until ownership and observability are explicit. The provider is a component; the access decision and the SLO remain the application's responsibility.
